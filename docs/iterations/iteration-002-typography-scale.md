# 迭代 002：平衡展示字体与功能可读性

日期：2026-08-02

## 目标

修复第一版“展示标题过大、正文和功能文字偏小、中文行高过紧”的排版失衡，同时保留酒店网站需要的编辑感、留白和视觉冲击力。修改范围限定为字号、行高与字距，不改变页面结构、内容、图片和交互动效。

## 修改前现状

受控浏览器中的计算样式测量显示：

| 场景 | 修改前 |
| --- | --- |
| 桌面首页主标题 | 158.4px / 114px 行高 |
| 桌面酒店详情主标题 | 201.6px / 131px 行高 |
| 桌面酒店名录标题 | 129.6px / 106px 行高 |
| 移动首页主标题 | 74.1px / 56px 行高 |
| 移动酒店详情主标题 | 93.6px / 61px 行高 |
| 移动酒店名录标题 | 66.3px / 54px 行高 |
| 正文与说明 | 11–14px |
| 导航、按钮、筛选与标签 | 7–10px |

问题不是整体同比例过大，而是层级的两端同时失衡：大标题接近海报比例，功能文字却小于稳定阅读范围。中文标题沿用英文展示字体的极紧行高后，笔画和换行也显得拥挤。

## 依据与证据等级

- A：用户直接指出字号存在问题。
- B：1440×900 和 390×844 两个视口下的计算字号、行高、元素高度和横向溢出测量。
- C：在不破坏原有视觉方向的前提下，对酒店编辑型网站层级进行设计修正。

## 迭代理念

保留“标题负责营造地点感，正文负责解释，功能文字负责行动”的三层结构，但不再通过极端大小反差制造高级感。新的尺度让标题仍然占据主导，同时确保中文段落、筛选器和预订操作不需要用户费力辨认。

## 设计

- 引入统一的流式字号变量：`hero`、`display`、`card`、`body`、`label`、`control`。
- 桌面首屏标题上限降至 138px，1440px 视口实际为 129.6px。
- 移动首屏标题限制在 58–64px，并把行高提高到 0.84。
- 中文章节标题移动端限制在 40–46px，行高提高到 1.08。
- 正文桌面使用 14–16px 流式范围，移动端统一为 15px。
- 功能按钮与导航提高到 11–12px；标签提高到 9–10px。
- 酒店详情、名录和预订页分别建立适合内容长度的独立标题上限，避免全部页面使用同一组超大 `vw`。

## 实现方法

- 在 `app/globals.css` 增加第 002 轮排版变量和覆盖层，集中管理字号而不拆散现有动效样式。
- 对首页主标题、章节标题、卡片标题、正文、预订栏、页脚、名录、详情和预订流程进行统一映射。
- 在 560px 以下重设流式变量，并为酒店详情主标题、名录中文标题、房型标题和预订步骤设置独立行高。
- 保留现有断点、布局、动画和减少动效规则。

## 验证结果

- 1440×900：首页、名录、详情和预订页的标题层级均已实测，无页面级横向溢出。
- 390×844：首页、名录、详情和预订页的标题层级均已实测，无页面级横向溢出。
- 首页英文标题仍保留编辑感，但不再遮蔽大部分建筑主体；移动端说明文字由一条灰色小字调整为稳定的两行正文。
- 浏览器 console 无 error 或 warning。
- `npm run lint` 与 `npm run build`：通过。
