# 迭代 001：研究基准与完整交互骨架

日期：2026-08-02

## 目标

建立一个独立的原创豪华酒店网站，不接入现有游戏官网，也不把官网素材搬进项目。第一轮必须同时覆盖首页沉浸感、酒店发现、酒店详情、房型和餐饮内容、预订路径、桌面/移动响应式，以及可以追溯的设计依据。

## 修改前现状

- 新项目只有 Sites/Vinext 初始骨架和通用预览占位页。
- 没有品牌、酒店数据、视觉素材、页面架构或业务交互。
- 初始 npm 脚本使用 Unix 环境变量写法，在 Windows PowerShell 下不能直接运行。

## 参考依据与证据等级

- A：万豪、丽思卡尔顿、四季和安缦当前官方页面的可访问结构与文案，详见 [基准研究](../research/hotel-site-benchmark-2026-08-02.md)。
- B：本地站点在受控浏览器中的 DOM、计算样式、交互状态和 390px 移动端布局测量。
- C：根据官方结构推导的原创比例、色彩、字体、镜头节奏和中文内容。

## 迭代理念

酒店官网的核心不是把组件摆得像，而是保持两条并行时间线：一条通过影像、留白和慢节奏建立“想去”，另一条让查询房价、比较酒店和预订始终清楚可达。因而本轮把叙事和转化做成同一套页面体系，而不是单独做一个首页海报。

## 设计

- 品牌：虚构的 `LUMEN HOUSE COLLECTION`，主张 `STAYS SHAPED BY PLACE`。
- 色彩：纸张灰、墨绿黑、骨白和陶土强调色；不沿用参考品牌的品牌色或标志。
- 排版：Cormorant Garamond 负责高对比英文标题，Noto Sans SC 和 Geist 负责中文及功能文本。
- 信息架构：首页 `/`、名录 `/hotels`、酒店详情 `/property`、预订 `/reserve`。
- 动效：2.4 秒首屏镜头推进、标题错峰、滚动进度、分层视差、视口入场、全屏菜单遮罩、预订抽屉、方向感酒店切换和减少动效分支。

## 实现方法

- 以 React/Vinext 构建共享 `SiteShell`，统一管理滚动状态、遮罩、焦点、Escape 关闭和正文锁定。
- 使用 `requestAnimationFrame` 把滚动位置写入 CSS 自定义属性，为首屏图像和标题提供反向位移；IntersectionObserver 负责内容入场。
- `/hotels` 使用客户端状态组合区域筛选与文本搜索；空结果提供一键清除。
- `/reserve` 实现日期与人数、房型、确认三步状态机；终点只保存页面内草稿，明确不产生真实付款或预订。
- 所有项目图片均为内置图像生成能力按原创制作规格生成，再转为 WebP；分享卡只生成一版并人工检查拼写后保存为 1200×630 PNG。
- Open Graph 图片 URL 在请求时从 `x-forwarded-host` / `host` 和协议头派生，避免硬编码部署域名。

## 验证结果

- `npm run lint`：通过。
- `npm run build`：通过；识别 `/`、`/hotels`、`/property`、`/reserve` 四条路由。
- 桌面端浏览器：首屏完成态、菜单入场/离场、正文滚动锁、预订抽屉、首屏视差、内容入场、酒店切换均已实测。
- 酒店筛选：搜索“雾麓”得到 1 条；清除后选择“海岸”得到 HAEON COAST 与 SORA HOUSE 2 条。
- 预订流程：选择 COAST HOUSE 后确认页显示 ¥38,400，本地保存结束态可达。
- 移动端 390×844：四条路由均无页面级横向溢出；全屏菜单修正了 `EXPERIENCES` 的截断；预订抽屉宽度为 390px 并锁定正文。
- 浏览器 console：最终没有 error 或 warning。

## 本轮修复

1. Vinext 开发环境的图片优化 worker 无法读取资产：对项目内静态图使用 `unoptimized`，消除运行时错误遮罩。
2. 浅色页面初始顶栏使用白字导致对比不足：为 `tone-light` 增加墨色顶栏。
3. 首版只有滚动入场、没有实质分层位移：增加滚动自定义属性与首屏图像/标题反向视差。
4. 390px 菜单中 `EXPERIENCES` 超出可视宽度：移动端字号从 14vw 调整为 12vw，并压缩字距。
5. starter 的 Unix-only npm 脚本无法在 Windows 运行：改为跨平台 `vinext` 命令。

## 遗留项

- 当前预订只是前端演示，不连接实时库存、会员账户、支付或邮件。
- 酒店详情使用一个代表性酒店模板；六家酒店尚未拥有独立 slug 页面和独立内容资产。
- 官方站第三方脚本加载不稳定，因此没有把官方页面逐像素截图差异作为证据。本项目也刻意不做商标和图片的像素复制。
